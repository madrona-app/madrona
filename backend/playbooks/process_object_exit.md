# Process an Object Exit

Use this when an object is leaving your institution — returning to a lender, going out on loan, transferring to another museum, leaving for conservation at an external lab, or departing for any other reason. The exit record documents the hand-off of custody and is the legal proof that the object left your care properly.

Object exits are the mirror of object entries. Every departure is a formal event that must be authorized, documented, and receipted.

## Where to go in Madrona

**Collections → Transactions → Departures** and press **New exit**. If the exit is linked to an outgoing loan or a deaccession, start from that record instead — Madrona will pre-link the exit.

## What to record

1. **Exit number** — a unique identifier following your institution's scheme.
2. **Exit date** — the date the object actually leaves (not the date you're filling out the form).
3. **Exit reason** — why the object is leaving: loan return, outgoing loan, transfer, deaccession disposal, conservation, photography, etc. This determines the downstream workflow.
4. **Recipient** — who is receiving the object. Record their name, institution, and contact details.
5. **Exit method** — how the object is being transported: courier, registered post, hand-carried, freight, etc.
6. **Exit authorizer** — the person who formally approved this departure. Not the person packing the box — the person whose authority covers the decision to let the object leave.
7. **Authorization date** — when the exit was approved.

## Condition at exit

Before the object leaves, file a condition report documenting its current state. This becomes the baseline for any claim if the object is damaged in transit or at the destination. Link the condition report to the exit record.

For loans out, this pairs with the condition report you'll file when the object returns — the two together form the legal basis for a damage claim.

## Receipt and acknowledgment

When the recipient confirms they have the object:

1. Set **Receipt acknowledged** to yes
2. Record the **acknowledgment date** and **reference** (their receipt number, email confirmation, signed form)
3. If a signed receipt exists, attach it via the signed documents section

Do not close the exit until receipt is confirmed. An unacknowledged exit means the object is in legal limbo — it left your custody but nobody confirmed it arrived.

## Signed exit form

A signed exit form is required before the object departs. Use the **Signed Documents** section to upload or reference the signed document. The system will block advancement to dispatched status until a signed exit form is recorded.

## Common pitfalls

- Dispatching without a signed exit form. The form is the legal record that authorizes the departure.
- Not recording the exit method. If something goes wrong in transit, you need to know how it was shipped.
- Closing the exit before receipt is acknowledged. "We sent it" is not the same as "they got it."
- Forgetting the condition report. Without a pre-exit condition baseline, damage claims are nearly impossible to substantiate.
- Recording the packing date as the exit date. The exit date is when the object actually crosses your threshold, not when it was prepared.
