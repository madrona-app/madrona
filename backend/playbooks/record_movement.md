# Record an Object Movement

Use this when an object physically moves from one location to another — within your building, between storage and a gallery, off-site for conservation or a shoot, or anywhere else. Every movement is a custody change and must be documented.

## Where to go in Madrona

**Collections → Transactions → Movements** and press **New movement**. You can also start one from an object's workspace via the **Location** tab.

## What counts as a movement

- Moving from storage to display
- Returning from display to storage
- Sending to the photo studio
- Sending out for conservation, framing, or exhibition prep
- Moving between buildings or sites within your institution
- Transferring between departments (e.g., from general collection to study collection)

Loan in / loan out transit is typically handled by the loan record itself, not a separate movement. But if you want an extra record of the internal handling of a loan object, a movement record is fine.

## What to record

1. **Object** — the specific object. For multi-object moves, create one movement record with multiple objects linked.
2. **From location** — where the object is *now*. Madrona will pre-fill this with the object's current location.
3. **To location** — where the object is going. Must already exist in the location authority; create the location record first if needed.
4. **Move date** — the actual date (or scheduled date if recording ahead of time).
5. **Reason** — display, storage, conservation, photography, packing, etc.
6. **Handler** — who is physically doing the move. Accountability matters.
7. **Authorized by** — who approved it. For anything above a trivial in-storage shuffle, this should be a curator, registrar, or collections manager.

## Handling and risk

For moves involving:

- **Large or heavy objects** — note the equipment used (hand truck, crane, forklift)
- **Fragile objects** — note the condition check before and after (or link a pre-move condition report)
- **Objects with legal restrictions** — NAGPRA items, cultural patrimony, sanctioned material — confirm the destination is cleared

## After the move

When the move is complete, Madrona updates the object's current location automatically. The movement record stays as part of the object's history — you can trace every location the object has been in from the **History** tab on its workspace.

## Common pitfalls

- Recording a move *after* the object has already moved, not before. The pre-move state is lost.
- Using free-text locations instead of the location authority. Future searches and reports fall apart when locations aren't standardised.
- Missing the handler or authorizer. If something goes wrong mid-move, the record is the only way to reconstruct who was involved.
- Forgetting to update condition if the object was handled heavily. A condition check bracketing any significant move is best practice.
